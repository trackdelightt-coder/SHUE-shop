# MSTAR 家具商店

給玩家瀏覽、下單 MSTAR 遊戲家具的網站。這個版本**只需要 GitHub + Google 帳號**就能上線，不用另外註冊 Render／Zeabur 這類架站平台。包含：

1. **買家頁面**（`index.html`）：瀏覽家具、加入購物車、自動計算總金額、送出訂單，網站全天候在線，不會休眠
2. **後台管理**（`admin.html`）：登入後可新增/編輯/刪除/上下架商品、查看所有訂單並更新訂單狀態、編輯商店公告
3. **下單通知**：買家送出訂單後，頁面會提醒買家截圖購物車畫面、私訊 Discord 給你確認訂單，你不用另外設定 Discord 或任何通知服務
4. **商品分類（可加 emoji）**：分類名稱可以直接輸入 emoji，例如「🛋️ 客廳」，買家頁面的分類選單就會顯示 emoji
5. **商店公告區**：買家頁面最上方會顯示公告（例如營業時間、交易方式、注意事項），可在後台「商店設定」分頁隨時編輯
6. **糖果／現金 雙軌計價**：每件商品同時設定「🍬 糖果價」與「💵 現金價（NT$）」兩組價格。買家在購物車面板選擇「本次訂單付款方式」，**同一筆訂單只能用一種付款方式**，不能一部分用糖果、一部分用現金

---

## 這個版本的架構（跟之前不一樣，先簡單了解一下）

- **畫面／程式碼**：放在 GitHub，用 GitHub 免費附贈的「GitHub Pages」功能直接把畫面變成一個網址，不用另外的架站平台，不會休眠
- **商品／訂單資料**：存在 Google 的 **Firebase**（一個資料庫服務，免費額度對小商店來說綽綽有餘），後台編輯商品、查訂單，都是直接讀寫這個資料庫
- **後台登入**：改用 Firebase 內建的帳號系統（Email + 密碼），不是自己存密碼在程式裡，比較安全

這兩個都只需要「登入你已經有的 Google 帳號」就能用，不用像之前那樣另外註冊 Render 或 Zeabur。

---

## 一、設定 Firebase（資料庫 + 後台登入）

### 步驟1　建立 Firebase 專案
前往 [firebase.google.com](https://firebase.google.com)，用你的 Google 帳號登入，點「**建立專案 / Create a project**」，專案名稱隨便取（例如 mstar-shop），一路照預設值按「繼續」到建立完成即可（不用開 Google Analytics 也沒關係）。

### 步驟2　開啟 Firestore 資料庫
左側選單點「**Firestore Database**」→「建立資料庫」。地區可以選 `asia-east1`（台灣）或離你近的地區。安全性規則先選哪個都可以，等一下我們會換成專用的規則。

### 步驟3　貼上安全規則
在 Firestore 頁面點上方「**規則 / Rules**」分頁，把裡面原本的內容全部刪掉，換成專案資料夾裡 `firestore.rules` 這個檔案的完整內容，貼上後點「發布 / Publish」。

> 這份規則的意思：商品和公告任何人都能看，但只有登入後台的人能新增/修改/刪除；訂單任何人都能「送出」，但只有登入後台的人能看到列表。

### 步驟4　開啟登入功能，新增你的管理員帳號
左側選單點「**Authentication**」→「開始使用」→ 登入方式選「**電子郵件/密碼**」→ 啟用。接著點「Users」分頁 →「新增使用者」，填入你要用來登入後台的 Email 和密碼（這組密碼只有你知道，之後就是用它登入後台，不會出現在任何程式碼或 GitHub 裡）。

### 步驟5　把 Firebase 設定值填進專案
左側選單點齒輪圖示「**專案設定**」→ 一般分頁 → 往下捲到「你的應用程式」→ 點 `</>`（網頁應用程式圖示）→ 應用程式暱稱隨便填 → 註冊後會出現一段 `firebaseConfig = {...}` 的程式碼。把裡面 6 個值複製起來，貼到專案資料夾裡 `public/js/firebase-init.js` 這個檔案對應的位置（把 `"貼上你的 apiKey"` 這種文字換成真正的值）。

> 這些值本來就是設計成可以公開的（不是密碼），不用擔心被別人看到，真正的安全防護是靠上面設定的「規則」和「登入帳號密碼」。

## 二、把網站放到 GitHub Pages（讓玩家可以連進來）

### 步驟1　申請 GitHub 帳號、建立 Repository
打開 github.com，註冊帳號（已經有的話直接登入）。點右上角「＋」→「New repository」，Repository name 填 `mstar-furniture-shop`。**這次要選「Public」（公開）**，不是 Private ── 因為 GitHub 免費版的 Pages 功能只能用公開的 Repository（程式碼會公開沒關係，因為密碼已經不在程式碼裡了，是存在 Firebase 那邊）。點「Create repository」。

### 步驟2　上傳資料夾
把我給你的 `mstar-furniture-shop.zip` 解壓縮（記得先照上面「一、」的步驟把 `firebase-init.js` 填好再上傳）。在 Repository 頁面點「uploading an existing file」，把資料夾內全部檔案拖曳進去，下方寫個說明文字，點「Commit changes」。

### 步驟3　開啟 GitHub Pages
進到你的 Repository，點上方「Settings」→ 左側選單「Pages」。「Source」選擇「Deploy from a branch」，Branch 選「main」，資料夾選「**/public**」，點「Save」。等 1-2 分鐘，畫面上會出現一個網址，長得像：
```
https://你的帳號.github.io/mstar-furniture-shop/
```
這就是買家看到的頁面！後台網址是這個網址後面加 `admin.html`。

## 三、開始使用

### 匯入範例商品
第一次使用時，後台「商品管理」分頁上方有一顆「📦 匯入 6 筆範例商品」按鈕，按一次就會把範例家具（沙發、餐桌、床等）放進資料庫，方便你先看整體介面和流程。之後可以直接編輯/刪除，或新增你自己的真實商品。

### 後台登入
網址後面加 `admin.html`，用「一、步驟4」設定的 Email／密碼登入。

### 買家下單流程
買家瀏覽商品、選付款方式（糖果或現金）、加入購物車、送出訂單後，頁面會提示他們截圖購物車畫面，私訊 Discord 給你確認訂單、討論交易細節（現金的話，收款帳戶只透過私訊提供，不要公開寫在網站上）。

## 四、之後怎麼維護

- 新增/修改/刪除商品、上下架、改公告 → 直接在後台網頁操作即可，資料即時更新，不用重新上傳任何檔案
- 查看所有訂單、更新訂單狀態 → 後台「訂單管理」分頁
- 如果我之後幫你調整了程式功能，會再給你新的資料夾，屆時只要重複「二、步驟2」上傳覆蓋舊檔案即可（`firebase-init.js` 記得保留你原本填好的設定值，不要被覆蓋掉）

## 五、注意事項

- 因為這個版本沒有後端伺服器，商品金額是在買家的瀏覽器裡計算後送出的；技術能力較高的人理論上有辦法在送出前竄改金額，這點跟有獨立伺服器把關金額的做法不同。對小型、熟人交易為主的商店來說風險較低，如果之後規模變大、想要更嚴謹的金額把關機制，可以再跟我說，我可以幫你評估要不要加回獨立伺服器。
- 商品圖片目前用網址連結（可以放你自己的圖床網址）。
- Firebase 免費方案（Spark）額度：每天讀取 5 萬次、寫入 2 萬次，對一般小商店來說用不完。要注意的是，免費方案如果哪天真的超過額度，當天會暫時無法讀寫（隔天額度重置就恢復正常），不會自動收費；如果之後量真的變很大，需要升級成付費方案（Blaze）才能超額繼續使用，這部分之後量大再跟我說，我可以幫你評估。
